# Exec plan: Gyral 0.3.1

Started 2026-10-07 on branch `gyral-0.3.1`. Beads `sabacc-cs0`, `sabacc-92i` (which
supersedes `sabacc-x56.11` from the [0.3 plan](../completed/2026-10-gyral-0.3.md)).

## Goal

Take up what the Gyral team is shipping in 0.3.1 in response to Sabacc's feedback
(bead `sabacc-nc4`), and simplify the code the workarounds needed.

## Done when

- The Three.js stage is its own `<sabacc-stage>` element: one `.view` property, teardown
  in `disconnectedCallback`; `stage-hook.ts` and the per-frame `isConnected` check are gone.
- On 0.3.1: object props take plain type guards (`checked()` optional), browser tests
  rely on `settled()` alone (no microtask loops), `emit()` calls use a typed
  `outputs<Out>()`, and `sabacc-card` uses the `svg` tag for its fragments.
- `npm run check` green, every drive path with no console errors, sizes per page
  measured against 0.3.0 (classic 90.4 KB, 3D 246.5 KB gzip).

## Steps

1. `<sabacc-stage>` custom element (`sabacc-cs0`). Needs nothing from 0.3.1.
2. 0.3.1-next tarballs as the team sends them, vendored under `vendor/gyral/<version>/`.
   (Installing 0.3.0 from npm first was dropped on 2026-10-09: the code uses 0.3.1 APIs.)
3. Adopt 0.3.1 (`sabacc-92i`): type-guard props, draining `settled()`, `outputs<Out>()`,
   the `svg` tag. `OUTPUT_EVENT` isn't needed (no non-Gyral parents left).
4. Measure, update FRONTEND.md, QUALITY_SCORE.md.
5. 0.3.1 final from npm (`sabacc-92i`): exact versions, registry SHA-256 checked against the
   final tarballs' sums, no `overrides`, no `vendor/`, no `COPY vendor` in the Dockerfile;
   check and drive green. Then move this plan to `completed/`.
